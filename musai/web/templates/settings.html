What MUSAI does with these

Moodle has no way to grant an app access on your behalf — no API key, no app password. So to read your course list, make a backup or run a restore as you, MUSAI signs in with your password the same way you do.

That means MUSAI can read these passwords, and it is worth knowing that before you store one. They are encrypted with a key that lives outside the database, they are never shown back to you or written to any log, and Delete removes them for good. Storing them is optional — you can type one in each time instead, and nothing is kept.

Opening pages is not counted. One page view costs about $0.0000008 — a millionth of a dollar, and one twelve-hundredth of a single analyst question. Recording it would cost more than the page view itself, so MUSAI meters only the two things that actually cost money: AI answers and browser jobs.

{# Show the working. A cost the reader cannot check is a number they have to take on faith, and this one is an estimate built on two vendors' published rates. #}
How this is calculated

MUSAI usage is our own number, covering both vendors, so you never have to think about which one a click reached. Rate card {{ rate_card.version }}:

  • {{ rate_card.model }} — ${{ '%.2f'|format(rate_card.gemini_in_per_mtok) }} per million tokens in, ${{ '%.2f'|format(rate_card.gemini_out_per_mtok) }} out.
  • Server time — ${{ '%.2f'|format(rate_card.usd_per_million_cu) }} per million compute units; a {{ rate_card.vcpu }} vCPU / {{ rate_card.gib }} GiB machine burns {{ rate_card.cu_per_second|int }} per second, so ${{ '%.8f'|format(rate_card.usd_per_second) }} a second.
  • Requests — ${{ '%.2f'|format(rate_card.usd_per_million_requests) }} per million.

Each line above is priced when it happens and never re-priced afterwards, so a rate change tomorrow cannot make last month look more expensive than it was.
